# Collector interruption and recovery

On 2026-11-05 the original run_core collector exited with status143 (SIGTERM), without a Python error traceback, before completing the planned cohort. The sender/cause of that process signal was not determined. Two core response journal entries for record_conflicts-r0 had no terminal client record. The PID watcher correctly moved on when the collector died, so context requests started after the collector's exit; this was not evidence of an intentionally concurrent context/core experiment.

collector-interruptions.json retains start records, excluded attempt IDs, and matching aggregate Magpie gateway evidence where available. Treat this as an administrative collector event, not a provider/model failure. Repeat the whole affected Go/GOAT trial pair with fresh conversations; retain original attempts/unknown usage separately. Other completed cohorts are not repeated. The original core script is saved as run_core.before-recovery.py; resumption changes only skip/recovery/journal parsing behavior, never task inputs, grading, caps, effort or feedback policy.

The durable coordinator is launched as a detached session to keep long experiment lifetime independent from an individual shell tool session. It waits for the existing context/tools coordinator to finish, then fills missing core/context/tools/low cases. Its PID, stage log and exit statuses are saved. All planned counts are validated before final analysis. Raw attempts are append-only; any superseded/administrative entries remain visible and their uncertainty is disclosed.

# Frozen comparison design, v2

Date: 2026-11-05, Asia/Shanghai. Exploratory larger follow-up to the first 50-call comparison. No preference between providers is encoded in scoring.

## Scope

Only standard DeepSeek V4.1 Flash through the running local Magpie gateway. Go=`opencode-go/deepseek-v4.1-flash`, GOAT=`commandcode-plan/deepseek/deepseek-v4.1-flash`. No routing groups, Fast variant, subscription changes, purchases, proxy changes or real project edits. Synthetic isolated files only. API credentials stay in existing configuration and are never copied into artifacts.

## Planned experiment

1. Twelve complex deterministic coding contracts, three fresh sessions each, same high effort, temperature 0, max output 65,536, paired and randomized in blocks. Main quality evaluation uses a maximum of two simultaneous requests per provider; pairs are matched in the same batch. Each task has equal weight, assertions are diagnostic rather than independent statistical samples.
2. Unsolved first attempts receive one feedback repair under the same effort and output cap; feedback is generated by a frozen validator and contains a bounded diagnostic excerpt. Failed/incomplete attempts remain in data. Repair is optional for initially successful attempts only in the sense that they require no repair.
3. Two isolated multi-file repository tool episodes, three fresh sessions each, high effort, up to 12 model turns. Tools can list/read the synthetic repo, write only enumerated source files, and run a fixed validation command. Models cannot change tests or invoke arbitrary shell. Both providers receive identical tool schemas, source and tool responses for identical actions. Quality is measured with hidden checks after episode termination.
4. Long-context exact extraction and cross-record reasoning at approximately 16K, 64K, 160K and 320K input tokens, three seeded datasets per size, high effort; usage-reported sizes are authoritative. Prompt construction, expected answers and hashes are saved before the calls. Test records include distractors and overrides; data is not treated as instructions.
5. Serial fixed-output latency pairs (12 per provider), followed by matched concurrency 1/2/4 workload batches (two repetitions each). These are separate strata and are not pooled with complex-task inference times. Cache cold/warm behavior is separately labeled. No intentional limit-exhaustion traffic.

## Measurement

- First event, first visible text/tool call, total time; status, finish reason, stream errors, response headers, actual route; input/cached/output/reasoning tokens. Time includes local Magpie behavior and current network.
- Independent benchmark worker validates generated code in a restricted process with CPU/memory bounds and no credentials. Only whitelisted standard-library imports are allowed. Restrictions are documented and violations distinguished from semantic errors.
- Transport read timeout 180 seconds. Application deadline 600 seconds per response is an availability threshold, not a task-wide budget; a timed-out response is recorded and remaining experiments continue. Deadlines and output lengths are not proof of model inability.
- Store final output and tool traces, but not reasoning prose. Retain reasoning token/character counts. Resume by completed trial identity to avoid duplicate calls after interruption.

### Frozen operational definitions

- A complete response requires HTTP 2xx, `[DONE]`, a non-error terminal choice with `finish_reason=stop|tool_calls`, and either nonblank final text or complete tool-call arguments. Usage is optional; missing usage is explicitly unknown. A length finish, stream error, missing finish, or deadline is incomplete. Semantic grading is separate.
- `first_event_ms` is the first parsed nonempty reasoning/text/tool delta; `first_visible_ms` is the first nonempty final-text or tool-call delta, ignoring reasoning and keepalives; `first_text_ms` excludes tool calls. The label TTFT is not used without these definitions.
- Launch both providers within each paired block in alternating/randomized order. The code quality workload has exactly two task pairs/batch (up to four shared-link streams); the serial latency phase provides separate calibration. No automatic external channel fallback. Shared interruptions are labeled, not deleted.
- A repair diagnostic contains at most three failed check entries, each truncated to 800 characters, plus any top-level error truncated to 800, with total feedback at most 4,000 characters. The previous final source is included if it exists. A fresh feedback conversation is used with the same session ID; reasoning prose is not required as input. Always one repair at the same high setting and 65,536 output cap, never an effort change chosen after the outcome.
- Tool episode cap counts every assistant model response, including errors/empty replies. Stop when the model returns a final answer without tool calls, when transport fails, or after the twelfth assistant response. Tool calls are executed serially in their declared order and results are appended in that order. A turn-cap hit is censored. Final hidden grading is run even if the model did not run the tests itself.
- Primary sampling unit is a task contract (N=12), not a test assertion or an assumed independent set of 36 problems. Three trials measure repeatability. Latency/quality uncertainty resamples whole task clusters. Context seeds are their own separately reported blocks.
- Context size labels are planned target bins and never relabeled after seeing usage. Store both planned target and actual tokens. Cold/warm descriptions require reported cache usage; otherwise call them first/repeated requests.
- The model instructions state Python 3.12, the standard-library import allowlist, 15 seconds CPU / 20 seconds validator wall time / 768 MiB memory. Restriction/resource failures are not silently counted as ordinary wrong answers. These are benchmark execution limits, not a financial budget.

## Analysis decided before results

- Primary endpoint: macro average task pass@1 for the 12 contracts, each with three repetitions. Secondary endpoints: repair success and end-to-end solved task throughput including failed/repair latency. Score completeness and semantic correctness separately. No composite weighted score will replace the dimensions.
- Paired latency ratios and confidence intervals use task/block resampling, not individual assertions as samples. Report distribution, task-specific wins, first-attempt and recovery separately. Quality uncertainty is reported; absence of significant difference is not proof of equivalence.
- Report quality versus speed decision plots and a workload-mix sensitivity grid. If a single convenience index is supplied, show its formula, raw inputs, uncertainty, and leave-one-task-out range. Both providers receive the same retry policy.
- High/low effort, serial/concurrent, peak/off-peak, and context size are separate strata. Prior 50 calls are background only, never silently pooled with this experiment.
- Identify shared network disruptions and unknown usage/cost on interrupted streams. Do not label HTTP 200 as success without a valid terminal event.

## Completion

All planned cases have terminal records and independently executable grading; negative-control validators detect intentionally broken submissions. Analysis includes every attempted call, failed cases, limitations, CSV/JSON, plots, and a reproducible evidence bundle. The sample count is an experimental design, not an imposed financial cap. Any unavailable tests are disclosed and not silently dropped.
